# AgentGate Website, Brand and Demo Pack Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax. This plan intentionally contains **no code**: each task names exact files, behaviour, test cases and commands. Tests first. Build only what a task states.

**Goal:** Ship a user/integrator-facing website (landing page + documentation), a shared brand, a polished admin console presentation layer, an accurate README, and a one-command demo mode with media — so AgentGate can be demonstrated to management and integrated by an outside developer.

**Architecture:** New `website/` Docusaurus 3 project (separate from the contributor docs in `developer-docs/`). Shared brand assets in `brand/`; small dependency-free Node check scripts in `tools/`. Presentation-only changes in `frontend/app/`. Demo mode is a PowerShell script beside the existing production deploy scripts. No product logic changes.

**Tech Stack:** Docusaurus 3.10.x (same as `developer-docs`: React 19, TypeScript ~6.0.2, classic preset, Mermaid theme, standard webpack bundler — **not** Rspack/Faster, which breaks on the Windows host), Node built-in test runner (`node --test`), Vitest for `frontend/app`, Playwright (capture only), PowerShell 5.1/7 for the demo script.

**Spec:** `docs/superpowers/specs/2026-10-09-website-and-demo-pack-design.md` (read it first; it is binding).

## Global Constraints
- **Offline:** the built site must load no external resource (no CDN, hosted fonts, analytics, hosted search). Fonts self-hosted via `@fontsource` packages.
- **No invented facts.** Docs state only what was run or is in verified repo docs/code. Unverified ⇒ omit or list as a limitation.
- **Licence undecided:** never use the words "open source"; say "licence: to be decided".
- **No external assets:** logo and diagrams hand-authored SVG; no stock images.
- **Snippets mirror repo files:** any config/code that exists in the repo is imported from the file via the generated-partials mechanism (Task 7), never retyped.
- **No product changes:** do not touch Go services, `deploy/` topology files, or `frontend/app` data/auth logic. Allowed exceptions: `deploy/prod/scripts/demo-mode.ps1` (new) and the presentation changes in Tasks 13–14.
- **Dependencies:** only those named in this plan, each justified in the task report: `@docusaurus/*@3.10.2`, `react`/`react-dom` ^19, `@fontsource/geist-sans` and `@fontsource/geist-mono` (verify exact package names and the OFL licence), `@easyops-cn/docusaurus-search-local`, `yaml` (API generator), `playwright` (devDependency, capture only). Nothing else without escalation.
- Standing project rules (HANDOFF.md, hardening plan): pathspec commits (`git add <paths>`; `git commit <same paths> -m ...`), **no AI/agent attribution, no Co-Authored-By**, never push/merge/tag, never `git add -A`. **Never stage** the quarantined `.ps1` deletions, or the untracked stray root files `h2.bundle`, `h3.bundle`, `update.ps1`, `update_ci.ps1`, `update_h3.ps1`. PowerShell (`.ps1`) work and anything needing Docker runs in the sandbox `agentgate-sandbox` (content via stdin / in-container edits only; bring commits back by bundle + `git update-ref`; do not rename or otherwise evade the security tool). Node scripts and `npm` for `website/` and `frontend/app` run fine on the Windows host.
- Branch: `feature/website-and-demo-pack`, cut from `feature/v1-production-readiness` **after the planner posts `hardening signed off` in the ledger**. Tasks 1–2 touch only new files (`brand/`, `tools/`) and may start earlier on a branch cut from the current head; do not touch `deploy/`, `.github/`, `docs/OPERATIONS/`, `README.md` or the clean-room/gate scripts until sign-off (the hardening work edits them).
- Per-task verification (website): from `website/`: `npm run build && npm run typecheck && npm test`. Tools: from repo root `node --test tools/test/*.test.mjs`. Console: from `frontend/app/`: `npm run build && npm test`.

## Review Focus
1. **Offline claim false-passes:** the offline check must fail if any built page/asset references an external host; it must also fail if it finds nothing to scan.
2. **Quickstart check false-passes:** the verifier must fail when it finds zero `verify` blocks, when a block is malformed, or when an expected-output assertion is missing from the output.
3. **Scenario data drifts from reality:** every attack-player entry must map to an existing gate test, and the displayed result must equal what that test asserts.
4. **Dark theme legibility:** both themes must pass the contrast test on text and status pairs; reduced-motion users get no auto-playing animation.
5. **Generated files out of date or committed by accident:** generated partials/API pages are gitignored and rebuilt by `prebuild`; the build must fail if generation fails.
6. **Binary bloat:** committed media stay under the size cap; large files never enter git history unnoticed.
7. **Broken links** in README and docs.

## Rulings made by the planner (change here, not mid-task)
- **P1:** one `deploy/prod/scripts/demo-mode.ps1` (PowerShell 5.1 + 7); no separate `.sh` (pwsh is available on CI and in the sandbox). Deviation from spec §8's "shell equivalent" — cost if wrong: none.
- **P2:** repo-file snippets reach the docs via a prebuild script that writes MDX partials into `website/docs/_generated/` (gitignored; underscore dirs are not routed). No `raw-loader`.
- **P3:** committed media cap: 15 MB total under `website/static/media/`, video ≤ 8 MB.
- **P4:** design tokens are duplicated (brand/, website/, frontend/app/) and kept equal by a parity check, not by shared imports.
- **P5:** Playwright runs in the official Playwright Docker image (Debian-based; Alpine cannot run its browsers), pinned to the same version as the npm dependency, with host networking inside the sandbox so `https://localhost:8444` works.
- **P6:** website tests are `node --test` scripts that inspect source data and build output; no Jest/Vitest in `website/`.
- **P7:** contrast test applies to primary/secondary text and status text pairs; "muted" text is exempt from the 4.5:1 rule but must not carry essential information (record any token you change and mirror it in brand/ and website/).
- **P8:** search is local-only; no Algolia.
- **P9:** repo URL in site/README is read from `git remote get-url origin`; do not invent a slug. If it is a placeholder, omit CI badges and "edit this page" links.
